### 지난 세션 (M12~M16, 2026-10-01~02)

- **방향 결정 — 06 문서** (2026-09-30 사용자 검토, D18~D21·D23~D29): 층 올리기형 마을(팀원별 일터), 진주 = 토큰값을 했는가, 팀장 = 시장, 마을 레벨·공공시설, 집 주인 표시, 캐릭터 누르기, 신문·날씨·설명서. M12~M20으로 나눠 만든다 (04 문서).
- **M12 경제 정리** (06 문서 3·4장, 01 문서 6장·D20·D21·D23):
  - 급여 = 서브에이전트 **실행**이 끝날 때 한 번, 도구 호출 수 × 26 × 품질 (계획은 작업 단위였으나 짝지어지지 않는 실행이 급여 0이라 실측 뒤 바꿈). 진주 1 = 비용 환산 토큰 1,000. 세금 20% → 마을 기금.
  - 뺀 것: 입주 지원금·물가·중앙은행(금리)·집·가구 관리비·완공 보너스·효율 급여 보정. 옛 `overrides.economy.priceIndex`·`centralBank`는 무시.
  - 팀장 = 시장: 지갑 = `economy.fund`, 팀장 토큰값·팀장 가구는 기금에서. 모자라면 0에서 멈추고(빚 없음) 날마다 `leaderUnpaid`로 기록. **시청 적자**(`economy.deficit`)는 오늘이나 지난 정산 날에 못 낸 몫이 있으면 켜지고, 못 낸 몫이 없는 날이 정산돼야 꺼진다.
  - 효율 순위 = 실행마다 일 점수(도구 호출 × 품질) 1점당 토큰. 경제 API `{ fund, deficit, history, plaza, members }`. 웹: 경제 패널 마을 기금 흐름 카드, 상단 바 기금 칩(적자면 위험 색), 집 지갑(팀장 = 시청 금고).
  - 실제 두 마을을 DB 복사본으로 재생해 확인: ETL은 팀원 모두 형편 OK·기금 흑자, agent_village는 팀장이 못 낸 몫이 세금의 약 20배.
  - 알려진 구멍(이어 받은 서브에이전트, 시작 없이 온 `SubagentStop`)은 그 뒤 **구간**(`<agent_id>#n`)과 암묵 시작으로 고쳤다 (04 문서 "이어 받은 서브에이전트 = 구간"·"구간 고침 1차" 줄).
- **M13 일터** (06 문서 5장·5.9, 01 문서 5장·8.3·8.5, 02 문서 6·8·9장, 03 문서 3.1):
  - 작업은 건물을 만들지 않는다 (작업 → 건물 묶기·`predict` 지움). 팀원마다 일터 = `VillageState.buildings`(`Building` 모양을 바꿈), id `w<n>:<팀원 id>`(n = 그 팀원의 몇 번째 일터 — 재생해도 같아 사용자가 지은 이름이 따라감), 3×3 부지(남 → 동, 건물은 왼쪽 위 2×2, 나머지는 앞마당). 코드: `core/rules/workplace.ts` (실행 시작 = 부지·현장, `finishRun` = 일 점수, 급여·토큰값 다 센 뒤 `raiseAll`, 하루 정산 = 자동 구매보다 먼저 `raiseAll`).
  - 일 점수 = 끝난 실행의 도구 호출 × 품질. 층 = 점수 · 마을 레벨 · 자재비: 75 · 225 · 450점, Lv.1 · 1 · 4 · 7, 자재비 **800 · 1,200 · 1,700**(급여 26 기준 실제 두 마을·성장 시뮬레이션으로 보정, 06 5.3). 큰 건물 뒤엔 두 번째 일터. 자재비를 기다리는 팀원은 가구 자동 구매를 쉼.
  - **마을 레벨은 M14가 만든다**: 지금 `VillageState.level` = 1 고정이라 3층·큰 건물은 "Lv.N 필요"로 멈추고 점수만 쌓인다 (실제 마을은 모두 2층 이하).
  - 웹 (임시 그림, M15 전까지): 3층 = 2층 그림 + 층 배지, 큰 건물 = 2층 그림을 3×3 가운데 + 배지 "큰 건물", 일하는 동안 비계·앞마당 자재 더미·게이지, 일터 얼굴 간판·이름표(집과 같은 `OwnerSign`). 일터 상세(`&building=w1%3Abackend-dev`: 층 스텝·게이지·다음 층 조건·최근 일·쌓은 일·이름 바꾸기), 격자 일터 카드, 상단 바 "일터 N곳", 집 지갑 "자재비 · 오늘"(`Member.materialsToday`).
  - 옛 `&building=b3` 주소와 작업 건물 시절 이름은 재생하면 사라진다 (실제 DB에는 일터 이름 바꾸기 줄이 없어 잃은 이름 0).
- **M14 레벨·공공시설** (06 문서 6장·6.4, 01 문서 3.3·6.2·8.1·9장, 02 문서 6·8·9장, 03 문서 3.1·8장, 05 문서 2장):
  - **하루 정산 순서** = 레벨업 → 일터 층(`raiseAll`) → 자동 구매 → 공공시설 하나 → 기록 → `today` 비우기 (`rules/economy.ts` `settle`, 레벨·공공시설은 `rules/village.ts`). 레벨업은 정산에서만 일어난다.
  - **마을 전체 일 점수** = `villagePoints` = 팀원 일터 점수 합(저장 안 함). 레벨 표 `village.levels`(Lv.2~10: 일 점수 1,500 · 3,500 · 6,000 · 10,000 · 18,000 · 30,000 · 45,000 · 65,000 · 100,000, 공사비 1,500 · 2,500 · 4,000 · 6,000 · 9,000 · 15,000 · 20,000 · 30,000 · 50,000). **성장 속도 ×10 (사용자 결정 D31)**: 점수·공사비·공공시설 값·일터 층 점수·자재비를 모두 10배로 했다(실제 기록에서 반나절에 Lv.6이라). 레벨업 = 점수가 차고 기금 ≥ 공사비 + 그날 팀장 토큰값 청구. 정산 한 번에 여러 레벨 가능, 레벨마다 `ring + 1`(상한 8).
  - **시청**: 첫 일에 북쪽 구역 광장 가까이 3×3(`VillageState.hall`), 층은 저장 안 하고 레벨의 시대(모래섬 마을 1층 · 산호 읍 2층 · 해저 도시 3층 · 해저 수도 해저 궁전). 팀장 집은 그대로, 시청을 누르면 경제 패널.
  - **공공시설**(`VillageState.publicWorks`, 지우지 않음): 가로등·벤치·꽃밭 1,000(자리가 남는 동안 되풀이), 공원 4,000·길 포장 6,000(Lv.4), 등대 20,000(Lv.7), 소라 탑(두 번째 랜드마크, Lv.10 레벨업에 포함). 자리는 규칙이 정함(가로등 = 길 양옆 줄에서 광장 끝부터 2칸째·그 뒤 4칸마다, 벤치·꽃밭 = 광장 둘레 6칸, 공원·랜드마크 = 가장 가까운 빈 3×3). 차례 = 열린 한 번짜리(공원 → 길 포장 → 랜드마크) 먼저, 그다음 가로등 → 벤치 → 꽃밭, 모자라면 건너뛰지 않고 모은다. **기금 우선**: 레벨업이 먼저, 점수가 찼는데 기금이 모자라면 공공시설을 짓지 않고 모으고, 공공시설은 그날 팀장 토큰값 청구를 남기고 산다.
  - **알림**: 레벨업 = 작업 기록 + 토스트(ref `@level:<n>:<시대>`, 글자는 이름 사전), 공원·길 포장·랜드마크 = 경제 기록 + 토스트(ref `@work:<종류>:<값>`), 가로등·벤치·꽃밭 = 활동 기록만. 입주한 팀원·팀장 환호, 섬 가운데 거품.
  - **자동 구매 보정**(×10 뒤): 예산 = 잔고 − max(예비 비율 몫, 다음 층 자재비). 층 자재비를 기다리는 동안 쉬는 규칙은 그대로.
  - **웹**: `sceneFromState`가 시청(`hall`)·공공시설(`public:<id>`)·공원 소품(`PARK`)·길 포장(`Ground paved`)을 임시 그림으로 만든다. 상단 바 "마을 공사" 자리 = 레벨 칸("Lv.4 산호 읍" + 진행 막대 + "일 a / b · 기금 c / d", 누르면 경제 패널), 경제 패널 기금 흐름 "레벨업·공공시설" 줄(`DayRecord.works`), 경제 API에서 `plaza` 뺌. 이름은 `theme-map.sea.json` `labels.eras`·`labels.works`.
