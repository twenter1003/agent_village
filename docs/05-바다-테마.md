## 3. 구현 구조 (안 A)

### 3.1 정본 id 원칙

- `packages/core`(이벤트, 프로젝터, 규칙, 배치)는 테마를 모른다. 상태에는 잔디 id만 들어간다.
- 테마는 `packages/web`에서만 쓴다: 에셋 고르기, 이름 보여 주기, 토큰, 월드 효과.
- 그래서 `raw_events` 재생 결과는 테마와 무관하게 같고, 골든 테스트도 하나다.

### 3.2 설정

- `.claude/tycoon.json`에 `"theme": "land" | "sea"` (없으면 `land`). 테마는 마을(프로젝트) 단위다.
- `species`, `accessory` 값은 잔디 id와 바다 id 둘 다 받는다. 설정을 읽을 때 대응표를 거꾸로 써서 정본 id로 바꾼다. `species`는 일대일이고, `accessory`처럼 여러 개가 한 곳으로 오는 경우는 표의 첫 키로 되돌린다 (`headlamp → glasses`).
- 설정 화면(M9)은 현재 테마의 이름과 그림을 보여 준다. 햄스터의 소품 칸은 "씨워크 헬멧 (고정)"으로 잠근다.

### 3.3 웹 쪽 구성

```ts
// packages/web/theme/index.ts
type ThemeId = 'land' | 'sea';
interface ThemePack {
  id: ThemeId;
  map: ThemeMap | null;            // land는 null (항등)
  rig: Rig;                        // land: rig.json, sea: mergeRig(rig.json, rig.sea.json)
  assets: () => Promise<AssetRegistry>;   // 테마별 지연 로딩 (assets/land, assets/sea)
  labels: LabelDict;               // land: game.default.json의 label들, sea: map.labels로 덮어씀
}

// 정본 id → 그릴 id
function resolveId(pack: ThemePack, group: 'species' | 'body' | 'roof' | 'tile' | 'furniture' | 'prop' | 'accessory' | 'carry', id: string) {
  const table = pack.map?.[group];
  if (!table || table === 'same') return id;
  return table[id] ?? id;
}
```

- 테마 전환 = 루트 요소의 `data-theme` 바꾸기 + 팩 교체. 여러 마을을 오가면(M9 마을 전환) 현재 마을의 테마를 따른다.
- UI 컴포넌트(버튼, 칩, 카드, 토스트)는 테마 분기 코드가 없어야 한다. `var(--ink)` 같은 토큰만 쓰면 `tokens-sea.css`가 알아서 바꾼다. 테마마다 달라지는 것은 아이콘 8개(5.2)와 글자뿐이다.
- 이름은 `t('facilities.library')`처럼 사전으로만 꺼낸다. 화면 코드에 "도서관"을 직접 쓰지 않는다.

## 4. 토큰

- `design/tokens.css` 다음에 `design/tokens-sea.css`를 불러온다. 선택자는 `:root[data-theme="sea"]`.
- **덮어쓰는 것**: 선·글자·바탕(`--ink` `--text` `--text-2` `--paper` `--cream` `--sunk` `--field` `--rule`), `--focus`(자홍 `#b0357c`), `--shadow-ink`, `--cap-edge`, `--lift-float`, `--glass`, `--metal-*`, `--currency`(진주), `--disabled-*`.
- **새로 생기는 것**: 바다 재질 램프(`--sand-*` `--gravel-*` `--basalt-*` `--coral-*` `--nacre-*` `--wreck-*` `--weed-*` `--brass-*`), 물속(`--water-bg-*` `--light-ray` `--bubble` `--fish-school`, `--sheen` = 보드의 흰 반사 `#ffffff`: 물결 빛 무늬·빛줄기·거품과 진주 반사점. M5 리뷰에서 손으로 쓴 `#ffffff`를 토큰으로), 생물 포인트, 바다 종 캐릭터 색.
- **그대로인 것**: 슬롯 색, 상태 색, 차트 색, 글꼴, 간격, 모서리, 선 굵기, `--coin`.
- `--coin`은 화폐이면서 UI 강조색(주 버튼, 선택, 진행 채움)이다. 바다에서도 강조색은 노랑 그대로 두고, 화폐 아이콘만 `--currency`(진주)로 바꾼다. 그래서 tokens.css에 `--currency`(기본값 = 코인)와 `--disabled-*`를 새로 넣었다. 화폐 아이콘과 비활성 버튼은 이 토큰을 쓴다.
- 대비 주의: 슬롯 6 청록과 회의 파랑은 물 배경과 밝기가 비슷하다. 넓은 면에 쓰지 말고 늘 외곽선·아이콘과 함께 쓴다 (바다 01 보드 메모).

### 5.4 점 무늬 규칙 (두 테마 공통)

"캐릭터 몸에 점이 너무 많아 징그럽다"는 의견을 받아 정한 규칙이다. 작은 점이 모여 있으면 사람에 따라 강한 거부감(환공포)을 느낀다. 피부처럼 보이는 면에서 특히 심하다.

1. 캐릭터 몸 표면에 작은 점을 여러 개 찍지 않는다.
2. 무늬가 종의 특징이면(점박이물범) 큰 점 3개 이하, 서로 떨어뜨리고, 바탕보다 한 단계만 어둡게 한다.
3. 재질 결(산호석, 현무암, 성게 돔, 조개 외투막)은 점 대신 선으로 긋는다. 바위는 짧은 틈 2줄.
4. 거품, 부표, 조약돌, 촉수 끝처럼 모양 자체가 동그란 것은 괜찮다. 문제는 면 위에 박힌 점 무리다.

## 6. 리그 차이

### 6.1 이동 포즈

- 게임 로직은 이동을 늘 `walk`로 요청한다. 그릴 때 `species.move`로 바꾼다 (`movePose`). 물범·수달·거북·복어는 `swim`, 햄스터만 `walk`.
- `swim`: 몸을 10~14 띄우고 약 −10° 기울인다. 발은 몸 아래에 붙게 같이 올린다. 4프레임 300ms.
- 바다의 `walk`는 헬멧을 쓰고 바닥을 걷는 걸음이라 잔디보다 느리고(프레임 450ms) 보폭이 작다.
- `stand`는 꼬리 흔들림 4°가 더해졌고, `carry`는 소품이 산호석 블록이다. 망치질·환호·말하기·쉬기는 잔디와 같다.

### 6.2 종 값

잔디 `rig.json`의 species와 비교해 필드가 늘었다. 리그 런타임(02 문서 7.4)이 이 값을 읽도록 넓힌다. 없는 필드는 잔디 기본값을 쓰면 되므로 잔디 쪽 동작은 바뀌지 않는다.

| 필드 | 뜻 |
|---|---|
| `arm`, `armR [rx, ry]`, `footR [rx, ry]` | 팔 색, 팔·발 타원 크기 (잔디는 `armRy`만) |
| `eye [x, y, rx, ry, 반사 r]` | 눈 위치와 크기. 잔디는 모든 종이 고정값 |
| `blush [x, y, rx, ry]` | 볼터치 |
| `faceOff [dx, dy]` | 얼굴 기본 위치. 포즈의 얼굴 이동은 그 위에 더함 (햄스터 0,−4) |
| `move` | `swim` 또는 `walk` |
| `nose` | 코 색. 복어는 없음, 햄스터는 분홍 + 잉크 테 |

### 6.3 소품

- 바다 소품은 모두 body 공간이다 (얼굴이 창 안에서 두리번거려도 소품은 몸과 같이 움직임). 몸통 경로가 모든 종에 같아서 어느 종에 씌워도 맞는다.
- 수달은 망치질 때 망치 대신 돌을 든다 (`props.hammer.variantBySpecies`). 해달·수달이 돌로 조개를 깨는 습성에서 따왔다.
- 씨워크 헬멧: 햄스터 전용이고 벗지 않는다 (물속에서 숨 쉬는 장치). 귀를 가리고, 창(62×42, 유리 28%)으로 얼굴이 보인다. 거품은 칼라 양옆에서 새어 올라간다. 호스는 그리지 않는다 (S7). 꼭대기 밸브만 남는다.

### 6.4 골든햄스터

- 털 `--hamster-fur #e9a35b`, 볼·배·팔 `--hamster-cream #fbf0dc`, 코·발 `--hamster-pink #f0a3a6`.
- 헬멧 창 안에서는 이마의 황금색과 아래쪽 크림색 볼주머니가 보인다. 볼주머니와 분홍 코가 햄스터라는 신호다. 흰 줄무늬 이마 같은 특정 캐릭터의 특징은 넣지 않는다.
- 귀는 헬멧 속, 꼬리는 너무 짧아서 그리지 않는다. `ear-l` `ear-r` `tail` 빈 칸은 남긴다.
- 황동 헬멧과 털색이 비슷한 노란 계열이라, 창 테두리 잉크선과 유리 틴트로 둘을 나눈다. 0.45배에서 얼굴이 헬멧에 묻히면 털을 한 단계 진하게 하는 쪽으로 조정한다 (11장).

### 6.5 새 바다 동물 추가

**부품 라이브러리 + 동물 도감 (2026-09-30, 01 문서 D15).** 동물을 매번 새로 그리지 않게, 종마다 따로 그리던 모양 중 여러 동물이 같이 쓸 수 있는 것을 부품으로 빼 두었다.
- 부품 = `SeaCritter.dc.html`의 `display="{{pt.<부품>}}"` 모양. 색은 종의 `face`(주둥이·얼굴 무늬·배)·`shade`(귀 안쪽·꼬리 끝·귀 날개)·`beak`(부리) 값을 쓴다 → 같은 부품을 다른 색으로.
  - 귀: `earRound`(둥근 귀), `earFlap`(작은 귀 날개). 꼬리: `tailRound`, `tailFeather`. 몸: `belly`. 얼굴: `maskHeart`(하트 얼굴 무늬), `muzzle`(주둥이), `whiskerPads`(수염 주둥이 둘), `noseBig`, `noseSmall`, `whiskers`(수염 선), `beak`, `beakSpot`(부리 끝 붉은 점 하나), `tusks`(엄니).
- 동물 = `rig.sea.json` species 한 줄: 이름, 털·팔·발 색, `parts` 목록, `face`·`shade`·`beak` 색, 눈·볼 좌표, 귀·꼬리 회전 중심, `move`, 기본 소품. 색은 `tokens-sea.css`에 토큰으로도 적는다 (03 문서 규칙).
- 부품만으로 되는 동물은 **그림 없이 데이터 한 줄**이면 된다. 새 부품이 필요할 때만 그린다 (그 부품은 다음 동물이 또 쓴다).
- 정본 id: 잔디 짝이 없는 새 동물은 바다 id를 정본 id로 그대로 쓴다 (`theme-map.sea.json` species에 `"gentoo": "gentoo"`). 바다 id가 기존 정본 id와 겹치면 안 된다 — 정본 `penguin`이 이미 바다거북이라 펭귄의 id는 `gentoo`.
- 배정: `game.default.json` `roster.speciesCycle` 끝에 붙인다 → 새 팀원이 순서대로 받는다 (01 문서 3.1-3).
- 1차 도감: 펭귄(`gentoo`: 하트 얼굴·배·부리), 북극곰(`polarbear`: 둥근 귀·주둥이·큰 코·둥근 꼬리), 바다코끼리(`walrus`: 수염 주둥이·엄니·수염), 바다사자(`sealion`: 귀 날개·주둥이·수염), 갈매기(`gull`: 부리·부리 점·깃털 꼬리). 모두 공통 몸 틀 그대로, 점 무늬 규칙(5.4) 지킴.
- 2차 도감 (D16, 부품 추가: `hood` 머리 덮개 · `headPale` 밝은 머리 · `earSmall` · `muzzleWide` 넓은 주둥이 · `nostrils` · `tailFluke` 고래 꼬리 · `trunkNose` 늘어진 코 · `beakTri` 큰 세모 부리 · `beakBent` 굽은 부리 · `beakLong` 긴 부리 · `bands` 흰 띠 · `tailFin` 물고기 꼬리 · `shell`·`plastron` 등딱지·배딱지(거북과 같은 모양, 색은 종 값) · `spikes` 머리 가시 · `tailLong` 긴 꼬리): 해달(`seaotter`), 흰동가리(`clownfish`), 퍼핀(`puffin`), 듀공(`dugong`), 플라밍고(`flamingo`), 하프물범(`harpseal`), 붉은바다거북(`loggerhead`), 갈색펠리컨(`pelican`), 코끼리물범(`elephantseal`), 황제펭귄 아기(`emperorchick`), 바다이구아나(`iguana`). 흰 동물이 몰리지 않게 색을 골랐다.
- **자동 변형** (01 문서 3.1-3): `variant` ≥ 1이면 털·팔 색을 염색 토큰(`--dye-<이름>`·`--dye-<이름>-d`, 8색: 흰·크림·먹색·적갈색·모래색·청회색·분홍·민트)으로 바꾸고, 무늬 부품 하나(`stripes` 이마 줄무늬 선 3개 / `patch` 한쪽 눈 큰 무늬 1개)를 염색의 어두운 톤으로 켠다. 염색 = (variant − 1 + 종 번호) mod 8, 무늬 = 홀수 variant는 줄무늬·짝수는 눈 무늬. 부품 색(face·shade·beak)과 종 고유 모양은 그대로라 동물은 알아볼 수 있다. 수달 귀·꼬리처럼 털색을 쓰던 종 고유 모양은 `{{c.fur}}`·`{{c.arm}}`으로 바꿔 염색을 따라간다(기본 모습은 같음).

`SeaRig.dc.html`의 "새 바다 동물 추가" 카드가 절차다. 요약하면: `rig.sea.json` species에 색·eye·blush·move 추가 → 없는 파츠는 빈 칸으로 남김 → 몸에 붙는 모양은 body 안, 머리에 쓰는 것은 accessory, 손에 드는 것은 hold-r 변형 → 헤엄치는 종은 `move: swim` → 5.4 점 무늬 규칙 지키기 → 바다 04 캐릭터 시트에 한 줄 추가해 7포즈 확인. 문어·해파리·해마처럼 몸통 모양이 다른 동물은 공통 리그를 못 쓴다 (03 문서 7장과 같은 한계).

## 11. 알려진 문제

| 문제 | 처리 |
|---|---|
| 바다 보드는 렌더링 검수를 하지 않았다 | 구현하면서 캔버스와 나란히 보고 어긋난 곳은 여기에 적기 |
| 바다 보드는 슬롯 3 = QA, 4 = 팀장, 잔디 데모는 3 = 팀장, 4 = QA | 슬롯은 실행 중 팀원 순서로 정해지고 테마와 무관하다. M11 비교는 구성(건물·소품·캐릭터의 종류와 자리)만 본다 |

| 복어 외부인은 잠정 디자인 | 잔디 외부인(01 문서 D6)과 같이 결정 |
| 물 배경 위 슬롯 6 청록·회의 파랑 대비가 낮다 | 넓은 면 금지, 외곽선·아이콘과 함께 |
| 월드 효과 타이머가 원본은 200ms | 150ms 전역 타이머 하나로 통일하고 이동 거리만 비례 조정 |
