## 1. 한 줄 요약

Claude Code의 서브에이전트 팀이 실제로 일하는 모습을, 동물 캐릭터들이 마을을 짓는 모습으로 보여 주는 **방치형 모니터링 웹앱**. Claude Code로 개발하면서 옆 창에 띄워 두고 본다.

- 주 화면: 데스크톱 브라우저 1440×900
- 그래픽: 전부 SVG, 아이소메트릭 2:1
- 개인용 로컬 앱. 인터넷 서버 없음

## 2. 목표와 범위

| 목표 | 설명 |
|---|---|
| 한눈에 상태 파악 | 누가 무슨 일을 하는지, 막힌 팀원이 있는지 마을만 보고 안다 |
| 진행이 쌓이는 재미 | 작업이 끝날수록 건물이 올라가고 절대 사라지지 않는다 |
| 성장하는 팀원 | 급여로 집을 꾸미고, 실제 작업 데이터로 성격(MBTI)이 천천히 바뀐다 |

**범위 밖 (하지 않음)**: 여러 사람 동시 접속, 클라우드 동기화, 모바일 대응, 게임 쪽에서 Claude Code를 조작하는 기능(읽기만 한다), 소리.

### 3.1 팀원 등록

> 2026-09-30 변경 (사용자 결정 D9): 팀원 = **그 프로젝트의 `.claude/agents` md 에이전트 + 그 프로젝트에서 실제로 일한 다른 에이전트**(사용자 공통 `~/.claude/agents`, 플러그인 등). 팀원은 마을(프로젝트)마다 따로다. 집은 **처음 일할 때** 짓는다 (3.3).

1. `.claude/agents/*.md`를 읽어 팀원 목록을 만든다 (frontmatter의 `name`, `description`). 읽는 때: 새 세션(`SessionStart`), 프롬프트마다(`UserPromptSubmit` — 세션 도중에 에이전트를 추가해도 다음 프롬프트에 목록에 오른다, 2026-09-30 실사용), 설정 저장. 바뀌었을 때만 roster 줄을 남긴다. 이 팀원은 처음부터 목록에 있지만 **입주 전**(집 없음, 마을에 안 보임, 팀원 패널에 "아직 일하지 않았어요")이다.
   - 서브에이전트가 시작되면(`SubagentStart`의 `agent_type`) 그 이름의 팀원이 입주한다: 집을 짓고 마을에 나타난다.
   - md에 없는 이름도(기본 에이전트 Explore·Plan·general-purpose 말고는) 처음 일할 때 팀원으로 등록하고 바로 입주한다. 설명(`description`)이 없어 직업은 이름으로만 고른다.
   - 입주 전 팀원의 md가 사라지면 목록에서 뺀다 (마을에 남긴 것이 없다).
2. 동물·직업·소품은 마을 설정 파일(tycoon.json 형식, `~/.subagent-tycoon/settings/<마을 id>.json` — D14)의 `members[name]`에서 가져온다 (md에 없는 에이전트도 이름으로 적으면 된다).
3. 없으면 자동 배정: 직업은 에이전트 이름(`name`)만 `jobPresets[].keywords`로 매칭(없으면 `fallbackPreset`). 설명(`description`)은 보지 않는다 (D17), 동물은 `roster.speciesCycle` 순서, 소품은 직업 프리셋의 `accessory`. 기본 순서는 곰·토끼·너구리·펭귄(바다: 물범·수달·햄스터·거북) — 팀장 기본 동물(펭귄)을 맨 뒤에 둬서 팀원 셋까지는 팀장과 겹치지 않는다 (M9 QA, 2026-09-30. 전엔 펭귄이 셋째라 세 번째 팀원이 팀장과 같은 거북이었다). 그 뒤로 **동물 도감**(D15·D16)의 새 동물이 이어진다: 펭귄·북극곰·바다코끼리·바다사자·갈매기, 해달·흰동가리·퍼핀·듀공·플라밍고·하프물범·붉은바다거북·갈색펠리컨·코끼리물범·황제펭귄 아기·바다이구아나 → 팀원 19명까지 동물이 겹치지 않는다. **팀장 동물(펭귄 = 바다거북)은 팀원 순서에서 뺀다** (2026-09-30, D16 — 동물이 넉넉해져서 팀장과 같은 동물인 팀원이 없게. 전엔 넷째 팀원이 팀장과 같은 거북이었다. 설정에서 직접 고르면 팀원도 거북이 될 수 있다). 도감에 동물이 늘면 순서 끝에 붙이기만 하면 새 팀원이 알아서 받는다(기존 팀원 동물은 안 바뀜).
   - **자동 변형** (D16): 도감을 한 바퀴 다 쓰면 다음 바퀴 팀원은 같은 동물에 변형 번호(`Member.variant`, 1부터 = 몇 번째 바퀴)가 붙는다. 변형은 털 염색(`--dye-*` 8색 중 하나, 종마다 시작점이 달라 같은 바퀴에서도 색이 갈림) + 무늬 하나(홀수 바퀴 이마 줄무늬, 짝수 바퀴 한쪽 눈 큰 무늬) → 몇 명이 와도 똑같이 생긴 팀원이 없다. 들어온 순서(슬롯)로 정해져서 한 마을 안에서는 늘 같은 모습. 설정에서 동물을 직접 고른 팀원은 변형 없음.
4. 슬롯 번호는 등록 순서(md는 파일 이름 가나다순, 그 뒤로 처음 일한 순서, 팀장이 있으면 팀장이 가장 앞). 슬롯이 색을 정한다 (`tokens.css`의 `--slot1..6`, 7번부터는 1..6을 되풀이 — D10).
5. **입주한** 팀원의 md 파일이 사라져도 팀원과 집은 지우지 않고 "떠난 팀원"으로 흐리게 남긴다 (건물이 절대 사라지지 않는 규칙과 같은 이유). 떠난 팀원이 다시 일하면 돌아온다. md가 없는 팀원(플러그인 등)은 떠나지 않는다.

### 3.2 외부인

- 기본 에이전트가 실행되면 해당 시설에서 외부인이 나온다. 모자 색으로 소속을 구분한다 (초록 Explore, 파랑 Plan, 노랑 general).
- 시설(도서관·설계사무소·인력사무소 = 바다 탐사 기지·해도실·인력 부두)은 **그 외부인이 처음 올 때** 북쪽 구역에 짓는다 (3.3).
- Explore는 도서관 주변, Plan은 설계사무소 주변에 머문다.
- general-purpose는 인력사무소에서 나와 지금 일하는 팀원의 일터(06 문서 5.9 `activeSite`)로 가서 자재를 나른다 (`visitors.general-purpose.helpsConstruction`).
- 외부인 기여는 작업 완료에 기록되지만 **건물 종류 결정에는 들어가지 않는다** (`buildings.visitorsCountForType = false`).

### 3.3 마을이 자라는 순서 (2026-09-30 사용자 결정 D8)

마을은 **빈 모래섬**(해초·바위 같은 자연 장식만)에서 시작하고, 에이전트가 일할수록 자란다. 한 번 생긴 것은 사라지지 않는다.

| 무엇이 | 언제 | 어디 |
|---|---|---|
| 광장(바닥·분수·게시판·벤치·가로등) + 십자 길, 팀장 입주(집) | 마을이 **처음 일할 때** — 첫 `PromptSubmitted`·`AgentRunStarted`·`TaskCreated` 중 먼저 온 것 (`VillageState.foundedAt`) | 가운데 / 서쪽 첫 부지 |
| 팀원 입주(집) | 그 팀원이 처음 일할 때 (서브에이전트 시작) | 서쪽, 광장에 가까운 순 |
| 시설 | 그 외부인이 처음 올 때 | 북쪽, 광장에 가까운 순 |
| 팀원 일터 | 그 팀원이 처음 일할 때 (3×3 부지, 06 문서 5장) | 남쪽 → 동쪽 |
| 시청 | 첫 일 (06 문서 6.3) | 북쪽 구역 광장 가까이 3×3 |
| 공공시설 | 하루 정산 때 마을 기금 (06 문서 6.2·6.4) | 길가 · 광장 둘레 · 빈 3×3 |
| 섬 넓히기 | 구역에 부지가 모자랄 때 (D10), 레벨업마다 (06 문서 6.1) | 사방 4칸씩 |

- `SessionStart`만 온 마을은 빈 섬이다 (마을은 생겼지만 아직 아무도 일하지 않음). 팀원 패널에는 md 팀원과 팀장이 "아직 일하지 않았어요"로 보인다.
- 새로 지어진 집·시설은 단계 바뀜과 같은 거품이 한 번 오른다 (화면 연출, 거품 효과 설정을 따름).
- 이유 (사용자): "처음엔 아무것도 없는 마을이고, 에이전트들이 어떤 프로젝트에서 일을 하면 점점 마을을 키우는 형태".

## 4. 팀원 상태

| 상태 | 들어가는 조건 | 나오는 조건 | 위치 · 포즈 |
|---|---|---|---|
| 작업 중 | 해당 팀원의 서브에이전트 실행 시작 (`SubagentStart`). **팀장은 메인 턴 동안**(`clock.mainTurn`, 마지막 훅 이벤트 뒤 `activeGapCapMs`까지 — 2026-09-30 실사용: 일하는 메인 세션이 "휴식 · 집"으로 보였다) | 실행 종료 (`SubagentStop`), 팀장은 턴 끝 | 자기 일터 앞 (팀장·공사 돕는 외부인은 가장 최근에 일을 시작한 팀원의 일터, 06 문서 5.9). 망치질, 도구 사용이 많으면 나르기와 번갈아 |
| 회의 중 | 회의 규칙(아래)에 해당 | 회의 끝 | 광장 게시판 앞. 말하기 |
| 휴식 | 위 어디에도 해당 없음 | 다른 상태 시작 | 자기 집 앞 또는 집 안. 쉬기 |
| 막힘 | 권한 요청 알림(`Notification` permission_prompt) 또는 같은 실행에서 도구 실패 `status.blockedOnToolFailureStreak`회 연속 | 다음 도구 성공 또는 실행 종료 | 제자리. 머리 위 느낌표 |

- 이동 중에는 걷기 포즈. 목적지가 바뀌면 길(십자 길)을 따라 걷는다.
- 일터 층이 오를 때 주인 환호 포즈 2초 (`buildings.cheerMs`, `Member.cheerUntil`). 1층은 환호 없이 활동 기록만 (06 문서 5.9).
- 세션이 끝나면(`SessionEnd`) 그 마을의 열린 실행을 모두 닫는다 — 새 세션(`SessionStart`)과 같은 처리 (M7). 끝난 시각 = `SessionEnd` 시각, 결과는 모름(`ok = null`: 품질 '실패'로 치지 않는다). 팀원은 작업 중·막힘에서 풀리고 팀장 막힘도 풀린다. `SubagentStop`이 오지 않은 채 Claude Code를 끄면 영원히 작업 중으로 남던 문제.

### 4.1 회의 규칙 (결정 D3 기본값)

- 사용자가 메인 세션에 프롬프트를 보내면(`UserPromptSubmit`) 팀장과 쉬고 있는 팀원이 광장에 모인다. 첫 서브에이전트가 시작되거나 `meetings.maxMs`가 지나면 흩어진다.
- `meetings.kickoffWindowMs` 안에 서브에이전트 `kickoffWhenParallel`명 이상이 시작되면, 현장으로 가기 전 `kickoffMs` 동안 광장에서 짧은 회의를 한다.
- 회의 말풍선 내용: 프롬프트 첫 줄 앞 20자 (없으면 "…"). 개인 정보가 걱정되면 설정에서 끈다.
- 사람이 친 프롬프트가 아니라 앱이 넣은 메시지(`<agent-message …>`, `<task-notification>`처럼 **태그로 시작하는 프롬프트** — 서브에이전트 보고·백그라운드 알림)는 회의를 열지 않는다. 메인 턴은 연다 (2026-09-30 실사용: "광장 회의 시작 · <agent-message from="가 떴다). 사람이 쓴 프롬프트 **앞에** 앱이 붙인 태그 블록(`<artifact-view-context …>…</artifact-view-context>` 등)은 떼고 남은 첫 줄을 안건으로 쓴다 — 수집기가 요약할 때(전체 프롬프트를 볼 때) 떼고 `injected`도 그때 정한다 (2026-09-30 실사용: 미리보기 20자가 태그 중간에서 잘려 "<artifact-view-conte"가 안건이 되고 걸러지지도 않았다). 옛 기록은 미리보기가 태그로 시작하면(20자에서 잘렸어도) 앱 메시지로 본다.

## 5. 작업과 일터

### 5.1 작업 (결정 D2 기본값)

1. 작업 = `TaskCreate` 한 건.
2~4. (M13에서 없어짐: 작업은 건물을 만들지 않는다 — 06 문서 5.8. 작업 묶기·예정 부지·공사 단계·N층은 팀원 일터의 일 점수로 바뀌었다.)
5. Task 도구가 없는 버전이면: `Agent` 도구 호출 한 번 = 작업 하나 (시작 = `PreToolUse`, 완료 = `SubagentStop`).
   - 구현 (2026-09-30 실사용 — 이 프로젝트에 훅을 달아 보니 작업 도구가 없는 환경에선 작업이 영영 안 생겼다): 마을이 `TaskCreate`를 한 번도 못 봤으면(`VillageState.taskTool` false) 메인 세션의 `Agent` 호출(`PreToolUse`, `tool_use_id`) = 작업 `agent:<tool_use_id>`, 제목 = 호출의 `description`, 곧바로 진행 중. 훅에 호출과 실행을 잇는 id가 없어 **같은 종류(`subagent_type` = `agent_type`)의 다음 `SubagentStart`**와 순서대로 짝짓고, 그 실행이 끝나면(`SubagentStop`) 완료. 호출이 실패하면(`PostToolUseFailure`) 작업을 지운다. 백그라운드 실행도 끝날 때 완료된다. `TaskCreate`를 한 번이라도 보면 그 뒤로는 대체하지 않는다(이미 만든 작업은 그대로).

### 5.2 일터 규칙

일터 규칙(층·게이지·자재비·대기·두 번째 일터·종류·이름)은 **06 문서 5장이 기준**이다 (D18·D19, M13 구현 메모 5.9). 이 문서는 아래 이름 바꾸기 규칙만 둔다.

### 5.3 이름 바꾸기

- 일터 이름 = 기본값 "<팀원 이름>의 <종류 이름>"(화면이 이름 사전으로 만든다) 또는 사용자가 지은 이름. 사용자가 일터 상세에서 바꾼다.
  - 사용자 이름: 앞뒤 공백을 떼고 연속 공백을 하나로, 1~24자(코드 포인트). 보이지 않는 글자(제어·서식 문자, 한글 채움 U+115F·U+1160·U+3164·U+FFA0, 점자 빈칸 U+2800)는 공백으로 보고 같이 정리한다 — 이모지를 잇는 ZWJ(U+200D)만 두고, 보이는 글자가 하나도 없으면 거절 (M6 리뷰). 바꾼 이름만 상태에 남는다 (06 문서 5.9).

### 5.4 불변 규칙

- 일터는 **절대 사라지지 않는다**. 층·일 점수·낸 자재비는 내려가지 않는다 (작업이 지워져도).
- 지운 작업은 끝이다 (M7): `deleted`가 된 작업에 뒤늦게 오는 상태 변경(`in_progress`·`completed`·`pending`)은 무시한다.
- 집·시설 부지는 2×2, 일터 부지는 3×3 — 배치 규칙은 `02-구현설계서.md` 8장.

## 6. 경제

모든 금액은 정수 진주 (화면 글자는 이름 사전, 05 문서 3장). 기본값은 `design/game.default.json`의 `economy`.

**진주의 뜻·식·규칙은 `06-도시와-경제.md` 3·4장이 기준이다 (D20·D21·D23).** 이 장은 그걸 요약하고, 구현 세부(활동 시간·토큰 셈·가구·진단)를 적는다. 식을 여기 다시 적지 않는다.

- 진주 = **토큰값을 했는가**: 끝낸 일로만 생기고(급여), 쓴 토큰과 산 것으로만 사라진다 (06 문서 3.1·3.2).
- 팀원은 일꾼(가치 = 자기 일 − 자기 토큰), 팀장은 시장(지갑 = 마을 기금, 가치 = 팀이 해낸 일 − 팀장 토큰). 세금이 기금으로 가고 팀장 토큰값을 기금에서 낸다 (06 문서 4장).

### 6.1 수입 (D20, 06 문서 3.3·3.4)

서브에이전트 실행이 끝나면 그 팀원이 급여를 한 번 받는다.

급여 식은 06 문서 3.4 (도구 호출 수 × `wagePerCall`(26) × 품질).

- 품질(`economy.quality`): 그 실행에서 테스트가 통과했고 실패가 없으면 `testsPassed` 1.2, 실행이 실패로 끝나면 `failed` 0, 그 밖 `noTests` 1.
- 작업이 아니라 **실행** 단위다. 도구 호출 수에 비례하니 쪼개도 합이 같다. 근거와 실측(실행 48개)은 06 문서 3.4.
- 세금: 급여의 `taxRate`(20%)가 **마을 기금**으로 가고 나머지가 팀원 잔고로 간다.
- 팀장(메인 세션)은 실행이 없어 급여가 없다. 팀장 몫은 세금뿐이다 (6.2). 외부인 실행도 급여가 없다 (잔고·집이 없다).
- 테스트 명령 판별: `Bash` 도구의 명령 자리(맨 앞, 또는 `npm`·`pnpm`·`npx`·`python -m` 같은 실행기 바로 뒤)에 `test`, `pytest`, `vitest`, `jest`, `go test` 등이 오고 성공(`PostToolUse`)이면 통과, `PostToolUseFailure`면 실패. `rm -rf test`·`echo test`처럼 인자로만 들어 있으면 테스트가 아니다 (M4 리뷰). 목록은 설정 `collector.testCommands`로 바꿀 수 있다.
- M12 정확한 규칙:
  - 끝난 실행 = `SubagentStop`(`AgentRunEnded`)을 받았거나, 그걸 잃고 새 세션·세션 끝이 닫은 실행. `AgentRun.wage`(세전)가 이미 있으면 준 것 — 한 번만 준다 (같은 이벤트를 다시 재생하거나 닫힌 실행이 다시 닫혀도).
  - 급여는 반올림한 정수(`round`), 세금 = `round(급여 × taxRate)`, 잔고 += 급여 − 세금, 기금 += 세금. 진주가 새지 않는다 (급여 = 세금 + 받은 돈).
  - 같은 이벤트 안에서 급여가 토큰 청구(6.2)보다 먼저다 — 새 팀원의 첫 실행이 괜히 형편이 어려워지지 않게.
  - 닫힌 실행은 토큰을 모르니 비용 없이 급여만 받는다 (기록이 빠진 만큼의 한계).
  - **이어 받은 서브에이전트** (2026-10-01, 3장): 마지막 구간이 끝난 `agent_id`에 시작이나 도구 호출(`PreToolUse`)이 오면 새 구간(실행)을 연다 — 시작 없이 도구 호출이 오는 때는 끝난 뒤 이어서 일함(예: 핸드백 도구), 세션 경계가 닫은 뒤에도 일함, 수집기를 도중에 켬. 주인은 도구 이벤트의 `agent_type`(없으면 앞 구간). 구간마다 급여 한 번. 기록 파일 토큰은 구간을 넘어 누적이라 **앞 구간 끝에서 읽은 합과의 차이만** 청구한다 (팀장 세션 누적과 같은 방식, 같은 누적이 또 오면 0). 이어 받은 구간은 `SendMessage`로 오므로 새 `Agent` 호출의 작업(5.1-5)과 짝짓지 않는다. 열린 구간에 시작이 또 오면(중복 전달, 끝을 잃은 구간을 이어 받음) 같은 구간으로 합친다 — 도구 수·토큰 합은 같다. 끝난 구간 뒤 늦게 온 `PostToolUse`는 끝난 구간에 붙는다 (비동기 훅 순서).
  - 시작도 도구 호출도 못 본 `SubagentStop`은 실행이 아니다: Claude Code 안쪽 포크(다음 입력 제안 `prompt_suggestion` — 도구 금지·기록 파일 없음, `agent_type` 빈 값, 메인 `Stop` 1~3초 뒤)라 일한 것도 토큰도 없다 (ETL 19개 전부, 2.1.278 확인).
  - `Task.salaryPaid` = 그 작업과 짝지어진 실행(`AgentRun.taskId`)이 받은 급여(세전) 합, 보여 주기용이다. 짝지어지지 않은 실행(워크플로가 띄운 서브에이전트, 백그라운드 실행)도 급여를 받는다.
  - **일 점수** = 도구 호출 수 × 품질. 급여·효율 순위(6.6)·(M13) 일터 게이지가 같은 단위를 쓴다 (06 문서 5.2).
  - 활동 기록에 실행마다 한 줄을 남기지 않는다. 그날 급여는 하루 정산 알림(6.2)에 합쳐 나온다.
- 빼진 것 (D20, 06 문서 3.5): 입주 지원금, 급여 물가연동·물가 지수·중앙은행(6.3), 집·가구 관리비, 건물 완공 보너스, 효율 급여 보정(6.7-5). 이유와 규칙 번호는 06 문서 3.5 표.

### 6.2 지출과 게임 하루 (게임 하루마다 정산)

- 지출은 둘뿐이다 (D20 규칙 3): **쓴 토큰**과 **산 것**(가구, 이후 일터 층·레벨업·공공시설). 시간만 지나서 빠지는 돈은 없다.
- **토큰 비용** (2026-09-30 사용자 결정 D11): 에이전트가 쓴 토큰만큼 낸다. 급여는 끝낸 일이니 적게 쓰고 많이 끝내는 에이전트가 부자.
  - 셈: 비용 환산 토큰 = 입력 × 1 + 출력 × 5 + 캐시 쓰기 × 1.25 + 캐시 읽기 × 0.1 (`economy.tokens.weights`, 모델 요금 비율). 진주 = 비용 환산 토큰 ÷ `economy.tokens.perPearl`(**1,000**, D20) 반올림.
    - 가늠 (2026-09-30 이 컴퓨터 기록): 서브에이전트 한 번 11만~120만 → 진주 110~1,200, 도구 호출 1번당 중앙값 약 10 (06 문서 3.4). 긴 메인 세션 하나 2,100만 → 21,000.
  - 누가 언제: 서브에이전트는 끝날 때(`SubagentStop`) 그 실행 몫을 **그 팀원이 자기 잔고에서**, 팀장은 메인 턴이 끝날 때(`Stop`) 그 세션에서 새로 쓴 몫을 **마을 기금에서** (D21). 외부인(Explore·Plan·general-purpose)의 토큰은 아무도 내지 않는다 (집·잔고가 없다).
  - 모자라면 가진 만큼 내고 0에서 멈춘다 (빚 없음). 팀원은 "형편이 어려움"(`hardship`), 팀장은 "시청 적자"(`economy.deficit`). 낸 비용은 사라진다. 팀장이 못 낸 몫은 날마다 `leaderUnpaid`로 기록해 기금 흐름에 보인다 (06 문서 3.3).
  - 형편이 어려움은 "마지막 진짜 청구를 다 냈는가"를 따른다. 들어갈 때 활동 기록 한 줄, 다 내면 풀린다.
  - **시청 적자는 붙어 있다** (2026-10-01, 06 문서 3.3): 오늘(`today.leaderUnpaid`)이나 지난 정산 날(마지막 `DayRecord.leaderUnpaid`)에 못 낸 몫이 있으면 켜지고, 그 뒤 팀원 세금이 들어와 청구를 다 내도 안 풀린다. **못 낸 몫이 없는 날이 정산되면** 꺼진다 (정산이 새 기록으로 다시 셈). 켜질 때만 활동 기록 한 줄이고 꺼질 땐 안 남긴다. 이유: 마지막 청구로 두면 팀원 세금이 들어올 때마다 꺼져, 못 낸 몫이 세금의 20배인 이 마을(agent_village)에서도 거의 안 보였다.
  - 반올림하면 0진주인 청구는 두 표시 모두 바꾸지 않는다.
  - 값을 못 읽으면(기록 파일이 없거나 형식이 바뀜) 비용 없이 지금처럼 — 게임이 멈추지 않는다.
  - 화면: 집 지갑 "토큰 비용 · 오늘"(팀장은 "팀장 토큰값 · 오늘"), 경제 패널 마을 기금 흐름(8.7), 하루 정산 알림.
- 마을 기금 = 팀장(시장)의 지갑 (D21): 세금 − 팀장 토큰값 − 팀장 가구 − 레벨업·공공시설.
- M7·M12 정확한 규칙:
  - 게임 하루 = **에이전트가 실제로 일한 시간(활동 시간)** `time.gameDayMs`(1시간)마다 (D4, 2026-09-30 사용자 결정). 정확한 정의는 아래 "활동 시간". 쉬는 동안(밤·주말·수집기만 켜 둔 때)은 날이 가지 않는다 → 정산도 멈춘다.
  - 정산은 `GameDayTick(day)` 때 지난 정산 다음 날부터 `day`까지 **하루씩** 한다 (활동 시간이 한 이벤트 사이에 여러 날을 넘어도 날마다 레벨업·자동 구매·공공시설). 모인 급여(`today`)는 첫 날 몫이고 나머지 날은 0. 같은 날 틱이 또 오면 아무것도 안 한다. `GameDayTick`은 raw 줄이 아니라 **프로젝터가 안에서 만드는** 이벤트다 (02 문서 6.1).
  - **활동 시간** (`clock.activeMs`, 2026-09-30):
    - 메인 턴 시작을 못 봤어도(수집기·훅을 턴 도중에 켬) 메인 세션의 도구 호출(`runId` 없음)이 오면 그때 메인 턴이 열린 것으로 본다 (2026-09-30 실사용: 훅을 설치한 턴의 작업이 쉬는 중으로 셌다).
    - 마을이 **일하는 중** = 직전 이벤트까지 반영한 상태에서 끝나지 않은 서브에이전트 실행(`endedAt` null)이 하나라도 있거나, 메인 세션 턴이 진행 중(`PromptSubmitted`부터 `MainTurnEnded`까지 — 새 `SessionStarted`·`SessionEnded`도 턴을 닫는다, `clock.mainTurn`). `MainTurnEnded` = `Stop`, `StopFailure`(API 오류로 끝난 턴), `Notification` `idle_prompt`(입력을 기다림 — 사용자가 중단하면 `Stop`이 안 온다) (리뷰 2026-09-30).
    - 이벤트마다: `activeMs += max(0, min(e.at, activeUntil) − now)` (직전 이벤트까지의 상태로 계산). `now` = 지금까지 본 가장 늦은 이벤트 시각(늦게 온 이벤트는 0). `activeUntil` = **일마다 그 일의 마지막 훅 이벤트 + `activeGapCapMs`** 중 가장 늦은 것: 메인 턴이면 `lastEventAt`(훅 이벤트만 — `Tick`·팀원 목록·사용자 행동은 뺌), 끝나지 않은 실행마다 그 실행의 `lastAt`(시작 + 그 `runId`를 단 이벤트). 일하는 게 없으면 0. 틱 없는 이벤트끼리면 곧 `min(e.at − now, activeGapCapMs)`.
    - `time.activeGapCapMs` 기본 600000(10분): 끝나지 않은(버려진) 실행·턴이 시간을 끝없이 흘리지 않게, **그 실행·턴의 마지막 훅 이벤트 뒤로는 최대 10분만** 센다. 수집기 시계 줄(`Tick`)이 몇 번 와도 이 상한은 그대로다 (시계 줄만으로는 시간을 늘리지 못함). 상한은 일마다 따로 잰다 (리뷰 2026-09-30): `SubagentStop`을 잃은 실행 하나는 그 실행의 마지막 이벤트 뒤 10분만 — 다음 턴들의 이벤트가 그 실행을 되살리지 않는다(마을 전체 마지막 이벤트로 재면 턴마다 10분씩 날이 흘렀다). 사용자 행동(이름 바꾸기·가구 사고 옮기기)과 팀원 목록은 에이전트 일이 아니라 상한을 다시 열지 않는다 (방치형 게임 클릭이 날을 흘리지 않게). 한 번에 10분 넘게 걸리는 도구 호출(긴 테스트)은 10분까지만 센다 — 알려진 한계.
    - 게임 날 = `day + floor((activeMs − dayStartMs) / dayMs)` (`clock.dayStartMs` = 오늘이 시작된 활동 시간, `clock.dayMs` = 지금 쓰는 하루 길이). 하루 길이가 한 번도 안 바뀌면 `floor(activeMs / gameDayMs)`와 같다. 이벤트 하나가 날을 올리면 프로젝터가 먼저 `GameDayTick { at: e.at, day: 새 날 }`을 규칙에 한 번 돌리고(정산·성격 `driftToday` 초기화) 그다음 그 이벤트를 처리한다.
    - **하루 길이를 바꾸면** (M9 설정 화면·tycoon.json `overrides.time.gameDayMs`, roster 줄에서 설정이 바뀜): 지금 날에서 이어 간다. 이미 지난 날을 새 길이로 다시 나누지 않고, 오늘 지난 몫이 새 길이보다 길면 새 하루 한 번만큼으로 자른다(`dayStartMs = max(dayStartMs, activeMs − 새 길이)`, 설정이 바뀌는 그 이벤트의 활동 시간까지 더한 **뒤에** — 앞에서 자르면 그 이벤트의 틈만큼 날이 더 넘어갔다, M9 리뷰). `time.gameDayMs`가 1000 이상 정수가 아니거나 `time.activeGapCapMs`가 0 이상 수가 아니면(사람이 손으로 고친 tycoon.json) 기본값을 쓴다 — 문자열이면 날이 NaN으로 영영 멈추고, 0이면 정산이 끝없이 돌아 수집기가 선다. 이유: `floor(activeMs / 새 길이)`면 60분 → 10분으로 줄이는 순간 지난 활동이 수십 날로 다시 나뉘어 정산이 한꺼번에 돌았다. 늘리면 오늘이 그만큼 길어질 뿐이다.
    - 수집기는 지금 시각 < `activeUntil`인 마을에만 `TYCOON_CLOCK_MS`(기본 10초)마다 `'clock'` 줄을 기록한다 → `Tick`(시간만 흐름) → 도구 호출 없이 긴 실행 중에도 날이 제때 넘어간다. 옛 DB의 `'clock'` 줄(벽시계 날 `day` 필드)도 `Tick`으로 재생하고 `day`는 버린다.
  - 한 날의 순서: 레벨업(06 문서 6.1) → 일터 층 → 자동 구매(6.4) → 공공시설 하나(06 문서 6.2) → 기록(`DayRecord`, 잔고는 정산 뒤, `works` = 레벨업·공공시설) → `today` 비우기. 관리비·물가·금리는 없다 (D20).
  - 레벨업·공공시설·시청 규칙은 06 문서 6.1~6.4가 기준 (`rules/village.ts`).
  - 알림: 그날 급여가 있으면 급여 토스트(자동) + 활동 기록 '경제' 한 줄 ("N일째 정산 · 급여 W · 토큰 T · 시청 L", 토큰·시청은 있을 때만). 급여가 없는 날(일은 했지만 끝난 실행이 없는 날)은 알림 없이 기록 표에만 남는다 — "급여 0"이 쌓이지 않게. **시청 적자**에 들어가는 순간은 정산과 따로 활동 기록 '경제' 한 줄 ("시청 적자 · 마을 기금이 팀장 토큰값을 다 못 냈어요", 토스트 없음, 켜져 있는 동안 또 못 내도 안 씀) + 상단 바 기금 칩이 위험 색이 된다 (8.1). 적자가 꺼질 때는 알림이 없다. 금액에는 화폐 단위를 넣지 않는다 (진주는 테마 글자, 05 문서 3장).

### 6.4 가구

- 가격 = `basePrice` 고정 (D20 규칙 2: 같은 것은 언제나 같은 값, `furniturePrice`). 색 변형은 같은 가격.
- 가구 id는 마을 번호(`f<n>`)가 아니라 **구매에서 정한다** (D30): 사용자가 산 가구 `u<구매 시각 ms>`(같은 팀원이 같은 ms에 또 사면 `-1`, `-2`…), 자동 구매 `a<날>.<팀원 id>.<그날 몇 번째>`. 규칙을 바꿔 재생해도 id가 같아 옮기기 줄(8.4)이 계속 맞는다. 옛 `f<n>`을 가리키는 옮기기 줄은 맞는 가구가 없어 아무것도 안 한다 (2026-10-01 한 번 초기화: 옮긴 가구가 자동 자리로 돌아감).
- 자동 구매 (`autoBuy`): 하루 최대 1개, 잔고의 `keepReserveRatio` 이상은 남긴다. 무엇을 살지는 성격이 고른다 (E는 꾸미기, I는 쉬기, J는 일하기 가구 선호 등 — 표는 02 문서).
  - M7·M12 규칙: 정산 때(6.2), 떠나지 않았고 집이 있는 **팀원**이 하루 `maxPerDay`개까지, 가격 ≤ 예산 = 잔고 − max(잔고 × `keepReserveRatio`, 남길 자재비)일 때만 (M14 보정, 06 문서 6.4). 남길 자재비 = 그 팀원 일터의 다음 층 게이지가 `saveFromGauge`(0.6) 이상이면 다음 층 자재비, 아니면 0 (D33). 태그는 두 축이 번갈아 고른다: 가진 가구 수가 짝수면 E/I 축(E → decor, I → rest), 홀수면 J/P 축(J → work, P → seed 난수로 태그 하나). 그 태그에서 살 수 있는 것 중 덜 가진 것, 같으면 설정 순서 (밖에 두는 `outdoor` 꽃밭은 빼고 — 방에 못 놓아 창고로만 간다). 없으면 그날은 사지 않는다(모은다). **팀장은 자동으로 사지 않는다** (D21 — 사용자가 사 주면 기금에서 나간다). 천 가구는 같은 가구 k번째가 `fabricColors[k]`(다섯 개 돌아감) — 두 번째부터 다른 색. 자리는 `findSpot`, 없으면 창고. 활동 기록 '경제' 한 줄 ("이름 가구 자동 구매 · 가격").
  - 성격 글자 = `personality.letters` (7장, 히스테리시스를 거친 글자). `personalityLetters()` 한 곳 — M8 전에는 직업 프리셋 `mbtiSeed`였다.
- 사용자는 가구 상점에서 팀원을 골라 직접 사 줄 수도 있다 (그 팀원 잔고에서 나간다. **팀장 가구는 마을 기금에서**, D21).
  - M7 규칙: 떠나지 않은 팀원(팀장 포함), 아는 가구, 천 가구면 `fabricColors` 중 하나·아니면 색 없음(`null`), 지갑(팀원 잔고, 팀장은 마을 기금) ≥ 가격. 사용자 구매는 `keepReserveRatio`·하루 한도를 보지 않는다 (자동 구매만). 산 값은 그날 가구 지출(`today.purchases`)에 들어가고 활동 기록 '경제'에 한 줄 ("이름 가구 구매 · 가격" — 가구 이름·화폐 단위는 테마 글자라 상태에 넣지 않는다). 자리는 8.4 `findSpot`.
  - 재생 규칙 (06 문서 3.5, 2026-10-01): 사용자가 직접 산 가구는 경제 규칙이 바뀌어도 남는다. 재생은 잔고 부족으로 버리지 않고(수집기가 살 때 이미 확인했다) 지갑에서 가진 만큼만 낸다 — 0에서 멈추고, 가격보다 적게 냈으면 가구에 `paid`(낸 돈)를 적는다. 없는 팀원·떠난 팀원·모르는 가구·색 오류 줄은 그대로 버린다.

### 6.6 효율 순위 (2026-09-30 사용자 요청 D12, D23으로 바꿈)

잔고는 누적이라 일을 많이 할수록 커진다 → "많이 일한 팀원"이지 "효율적인 팀원"이 아니다. 효율은 잔고와 따로, **양에 무관한 비율**로 본다. 잔고는 이미 토큰값이 빠진 값이라(6.2) 효율은 모니터링 지표로 두고 급여에 다시 섞지 않는다 (6.7-5).

- 지표 = **일 점수 1점당 토큰** (D23, 06 문서 3.6). 일 점수 = 도구 호출 수 × 품질(6.1). 적을수록 효율. 작업 1건당(D12)은 쪼개면 순위가 오르는 구멍이라 바꿨다.
  - 팀원마다 `eff.recent` = 끝난 실행마다 한 줄 `{ runId, tokens, credit }`. `credit` = 그 실행의 일 점수, `tokens` = 그 실행의 비용 환산 토큰(6.2, 실행이 끝나 청구할 때 더한다). 최근 `efficiency.window`(20)줄만 둔다.
  - 1점당 토큰 = `recent`의 토큰 합 ÷ credit 합 (`perPoint`). 실패한 실행은 credit 0이라 토큰만 분자에 들어간다. 일 점수가 0이면 꼴찌.
- 순위: 입주했고 떠나지 않은 팀원 중 `recent`가 `efficiency.minTasks`(3, 이름은 그대로, 뜻은 실행 수)줄 이상인 팀원만, 1점당 토큰이 적은 순(같으면 슬롯 순). 모자라면 "실행 n/3번"(`few`), 토큰이 0이면(기록 파일을 못 읽음) "토큰 기록 없음"(`noTokens`) — 둘 다 순위 밖. 끝낸 실행이 아직 없으면 "끝낸 실행 없음", 일 점수가 0이면(실패·도구 없음만) "실패만"으로 꼴찌에 적는다.
- 팀장은 순위에서 뺀다: 메인 세션 토큰은 사용자와의 대화·지휘 몫이고 팀장은 급여를 받는 일꾼이 아니다 (D21). 대신 **마을 전체** 한 줄 = (팀원·팀장·외부인이 쓴 비용 환산 토큰 합) ÷ 끝난 모든 실행의 일 점수 합, 그리고 그중 팀장 몫 %.
- 실행 크기가 달라도 1점당 값이라 견줄 수 있다 (실행 길이와 거의 상관없음, 06 문서 3.4 실측). 직업이 다르면 일이 다르니 화면에 직업을 같이 보인다.
- 알려진 한계: 닫힌 실행(6.1)은 토큰을 몰라 `tokens` 0으로 한 줄이 들어가 값을 조금 낮춘다 — 그 실행을 이어 받은 구간이 끝나면 닫힌 구간 몫까지 그 구간에 얹힌다(누적 차이라 합은 맞다). 이어 받은 서브에이전트는 2026-10-01부터 구간마다 실행·효율 줄 하나다(6.1, 전엔 새 시작이 실행 자료를 바꿔 급여 목록이 적게 세고 토큰은 누적 전체가 다시 청구됐다). 시작 없이 온 `SubagentStop`(ETL 19개)은 다음 입력 제안 포크라 실행이 아니다(6.1).
- 화면: 경제 패널 "효율 순위"(8.7), 집 지갑 아래 한 줄(8.4).

### 6.7 토큰 진단 (2026-09-30 사용자 결정 D13)

목적: 낭비하는 에이전트는 불리하게, 잘 쓰는 에이전트는 유리하게(점수판) + **왜 토큰을 먹는지, 어떻게 줄이는지** 알려 주기(진단). 에이전트는 마을을 못 보므로 실제 절약은 사람이 에이전트 설정을 바꿀 때 일어난다 → 진단에 무게. 에이전트에게 팁을 자동으로 넣지 않는다(훅이 응답을 기다려야 하고 토큰도 더 씀 — "Claude Code를 막지 않는다" 규칙).

1. **모델 단가** — 비용 환산 토큰 = 그 호출의 요금을 "Opus 5.5 입력 토큰 수"로 바꾼 값(기준 $4/MTok = 1). 2026-09-30 공식 요금표(`economy.tokens.models`, 위에서부터 처음 맞는 것):
   - 종류 무게(모든 모델 같음): 입력 1, 출력 5, 캐시 쓰기 5분 1.25, **1시간 2**(`cacheWrite1h`), 캐시 읽기 0.1 — 단 **Opus 5.5는 0.05**, Fable·Mythos 5.1은 0.025.
   - 모델 배율(입력 단가 ÷ $4): Fable·Mythos 2.5, Opus 4·4.1 3.75, 그 밖의 Opus(4.5~5) 1.25, Opus 5.5 1, Sonnet 5.x 0.5, Sonnet 4.x 0.75, Haiku 4.5 0.25, Haiku 3.5 0.2. **빠른 모드**(`speed: fast`) × `fastScale` 2.
   - 모르는 모델과 모델 정보가 없는 옛 기록은 배율 1·캐시 읽기 0.1 (D11 때와 같음 → 옛 기록 재생 결과 그대로). 미국 전용 추론(×1.1)은 셈하지 않는다.
2. **토큰 영수증** — 수집기가 기록 파일의 호출 순서대로 맥락 크기(입력 + 캐시 쓰기 + 캐시 읽기)를 보고 토큰을 원인별로 나눈다 (숫자와 도구 이름만, 02 문서 2.3):
   - **기본 맥락**(`base`): 첫 호출 전부(시스템 프롬프트·도구 정의·CLAUDE.md·지시) + 뒤 호출마다 캐시 읽기 중 첫 맥락 크기만큼. 서브에이전트는 이게 곧 시작비.
   - **도구 결과**(`tool:<이름>`): 결과가 들어간 다음 호출의 맥락 증가분(앞 호출 출력 중 생각을 뺀 몫을 제외)을 그 사이 결과들에 글자 수 비율로 나눈 크기(글자 수보다 크지 않게). 그 호출의 캐시 쓰기 + 뒤 호출마다 캐시 읽기. 맥락이 앞 호출의 절반 아래로 줄면(압축) 그때까지의 결과는 더 안 읽힌 것으로 본다. 실측 2026-09-30: 결과 1글자 ≈ 0.6토큰, 증가분이 음수인 적 없음.
   - **캐시 재작성**(`rebuild`): 캐시 쓰기 − 맥락 증가분 (캐시가 풀려 맥락 전체를 다시 씀).
   - **출력**(`output`)과 **대화 누적**(`talk`) = 나머지 (자기 출력·프롬프트를 다시 읽기 등).
   - 원인별 값은 그 실행에서 가장 많이 쓴 모델의 무게로 환산하고, 대화 누적 = 실제 비용 − 나머지 합(0 아래면 0).
   - 팀원마다 지금까지 합(`receipt`: 원인별 비용, 실행 수, 호출 수, 모델별 비용). 팀장은 메인 턴마다 세션 누적과의 차이(`mainUsage`, 최근 20세션만 — 스냅샷이 세션마다 커지지 않게). 영수증 전부터 청구하던 세션과 20개 밖으로 치운 세션이 이어지면 그 턴만 "누적 비용 × tokens 차이 비율"로 청구하고 원인은 누적 비율대로 나눈 뒤, 다음 턴부터 정확히. 외부인은 없음.
3. **처방 팁** (규칙, 모델 호출 없음 → 토큰 0). 영수증 비중이 기준을 넘는 원인마다 한 줄, 큰 순 최대 3줄:
   - 기본 맥락 35% 이상: 팀원 "작은 일은 묶어서 맡기거나 팀장이 직접, 에이전트 md를 짧게" / 팀장 "안 쓰는 MCP 서버를 끄고 CLAUDE.md를 짧게".
   - 도구 결과 20% 이상: 도구별 — Bash "출력을 줄이기(head·grep·조용한 옵션)", Read "필요한 부분만(offset·limit), 큰 파일은 Grep 먼저", WebFetch·WebSearch "필요한 부분만 묻기", Grep·Glob "검색 범위 좁히기", MCP 도구 "화면 전체 대신 필요한 요소만", 그 밖 "결과를 필요한 만큼만".
   - 캐시 재작성 10% 이상: "오래 쉬었다 이어 가면 캐시가 풀려 대화 전체를 다시 써요".
   - 출력 20% 이상: "에이전트 md에 '보고는 5줄 이내'".
   - 대화 누적 40% 이상: 팀원 "호출이 많아요(실행당 N번) — 파일 경로·완료 기준을 적어 주기" / 팀장 "대화가 길어요 — /compact 하거나 새 세션".
   - 팀원이 Opus·Fable을 쓰고 실행당 호출이 8번 이하: "짧은 일이 대부분 — md에 `model: sonnet` 또는 `haiku`".
   - 팀원 실행의 도구 재시도가 도구 호출의 15% 이상: "실패·재시도가 많아요 — 권한·환경 확인".
4. **팀장 대화 크기 게이지** — 메인 턴이 끝날 때 마지막 호출의 맥락 크기(`mainCtx`). `efficiency.leaderCtxWarn`(20만)을 넘으면 세션마다 한 번 알림("호출마다 약 N씩 다시 읽어요 · /compact나 새 세션"), 압축으로 기준 아래가 되면 다시 알릴 수 있다. 호출당 다시 읽기 = 맥락 × 캐시 읽기 무게 × 모델 배율.
5. **(없어짐, D20)** 급여 보정·같은 직업끼리 비교. 토큰값이 급여와 같은 크기가 돼 효율이 잔고에 이미 들어가서(06 문서 3.5) 보정까지 하면 두 번 센다. 번호는 다른 문서가 가리켜 둔다.
6. **비싼 실행 알림** — 팀원 실행 비용 > 그 팀원 최근 실행 비용 중앙값 × `efficiency.alert.ratio`(3), 표본 `minTasks`(3)실행 이상, 비용 `alert.minTokens`(10만) 이상이면 알림 + 활동 기록 한 줄(주원인 같이).
- 화면: 집 화면 "토큰 영수증" 카드(원인별 막대·모델·팁, 팀장은 대화 크기 게이지), 경제 패널 효율 순위 줄에 주원인(8.7), 알림 `tokens`(9장).

## 7. 성격 (MBTI)

- 초기값: 직업 프리셋의 `mbtiSeed`를 축마다 25 또는 75로.
- 축 점수 0~100 (0 = 앞 글자, 100 = 뒤 글자). 최근 `personality.window`개 작업의 지표로 목표값을 구하고 EMA(`emaAlpha`)로 따라간다. 게임 하루(에이전트가 일한 시간 1시간, 6.2 활동 시간) 이동은 `maxDriftPerDay` 이하.
- 글자는 `flipHysteresis`를 넘을 때만 바뀐다 (45 아래면 앞 글자, 55 위면 뒤 글자, 사이면 유지).

| 축 | 앞 글자 쪽 (점수 ↓) | 뒤 글자 쪽 (점수 ↑) |
|---|---|---|
| E / I | 다른 팀원과 동시에 일한 비율, 회의 참석 | 혼자 긴 실행, 회의 불참 |
| S / N | 읽기·검색·작은 편집·테스트 비중 | 웹 검색·새 파일 작성·큰 편집 비중 |
| T / F | 최종 보고의 `lexicon.thinking` 단어 | 최종 보고의 `lexicon.feeling` 단어 |
| J / P | 만든 순서대로 완료, 재시도 적음, 도구 전환 적음 | 순서 바뀜, 재시도·도구 전환 많음 |

- 바뀌는 중인 축은 UI에서 라벨·라벤더 표시 ("T가 F 쪽으로 38%").
- 이유 문장은 가장 크게 움직인 지표로 만든다 ("리뷰 코멘트에 칭찬이 늘어서").

M8 정확한 규칙 (`core/rules/personality.ts`):

- **표본**: 작업이 `completed`가 된 그 이벤트에서, 그 작업의 기여 팀원마다 표본 하나 (`Personality.samples`, 최근 `window`개 — 0 이하면 남기지 않아 성격이 안 움직인다). 기여 팀원 = 5.3 기여 구간(`shares`)과 실행이 겹친 팀원, 겹친 실행이 없으면 팀장. 외부인은 성격이 없다. 같은 작업이 창 안에 이미 있으면 다시 넣지 않는다. 지표는 그 팀원의 겹친 실행으로 센다 — 도구 수는 실행 전체(작업 구간으로 자르지 않음, `Task.toolCalls`와 같은 방식). 축마다 0~100, 셀 것이 없으면 `null`.
  - **E/I** = 평균(혼자, 불참) × 100. 혼자 = 1 − (작업 구간 안 내 실행 시간 중 다른 팀원 실행과 겹친 비율), 실행이 없으면(팀장) 뺀다. 불참 = 마을의 가장 최근 회의(누구든 참가한, 표본 시각까지)에 없었으면 1, 있었으면 0, 회의가 한 번도 없었으면 뺀다. 회의 참가는 참가자 목록에 들어간 시각으로 `Personality.lastMeetingAt`에 남긴다 (킥오프에 늦게 합류해도 참가).
  - **S/N** = N ÷ (S + N) × 100. S = 읽기·검색·작은 편집·테스트 명령, N = Write(새 파일 작성으로 본다 — 덮어쓰기와 구분 안 함)·웹·큰 편집(편집 내용 `chars` ≥ `personality.bigEditChars` 400). 테스트가 아닌 셸·계획·기타 도구는 안 센다. 호출 한 번에 한 번 (Pre, Pre가 없으면 Post — `toolCalls`와 같은 자리). `ToolUsed.chars` = 편집·쓰기 내용 글자 수 — Edit `new_string`, Write `content`, MultiEdit `edits[].new_string` 합, NotebookEdit `new_source` (숫자만, 02 문서 2.3).
  - **T/F** = F ÷ (T + F) × 100. 겹친 실행의 최종 메시지(요약본 `lastMessage`, 앞 2000자)에서 `lexicon.thinking`(T)·`lexicon.feeling`(F) 낱말이 나온 횟수 — 대소문자 무시, 부분 문자열 ("fixed"는 fix). 작업 완료 뒤에 끝나는 실행의 메시지는 이 표본에 못 들어간다. `collector.keepLastMessage: false`면 새 표본은 늘 `null`이고, 끈 동안은 T/F 목표도 없는 것으로 본다 → 끈 순간부터 T/F는 움직이지 않고 바뀌는 중에도 안 뜬다 (창 안에 켜 둔 때의 표본이 남아 있어도). 설정은 그 시점 roster의 tycoon.json이라 재생도 같다. 켜 둔 동안 저장된 요약본은 지우지 않으므로(raw 불변) 다시 켜면 창 안 옛 표본이 다시 당긴다.
  - **J/P** = 평균(순서, 재시도, 전환) × 100, 없는 항목은 뺀다. 순서 = 이 팀원 창 안의 앞 표본 중 이 작업보다 **나중에 만든** 작업이 있으면 1(순서 바뀜), 아니면 0. 재시도 = 실패한 도구를 바로 다음 호출에서 다시 부른 수 ÷ 호출 수 (호출 0이면 뺌). 전환 = 앞 호출과 다른 도구를 부른 수 ÷ 실행마다 (호출 − 1)의 합 (0이면 뺌).
- **갱신**: 목표 = 축마다 창 안 표본의 `null`이 아닌 값 평균 (없으면 그 축은 안 움직임). 표본이 들어올 때마다 축마다 `점수 += emaAlpha × (목표 − 점수)`, 단 그날 그 축이 움직인 양의 합(절댓값, `driftToday`)이 `maxDriftPerDay`를 넘지 않게 자른다. `driftToday`는 `GameDayTick`마다 0 — 활동 시간이 한 이벤트 사이에 며칠을 넘어도 틱 한 번에 한 번 (표본은 틱 사이에만 들어와서 날마다 나눌 것이 없다). 틱은 프로젝터가 활동 시간으로 만든다 (6.2) — 쉬는 동안엔 한도가 풀리지 않는다.
  - 완료 기준 계산 (M8): 목표가 계속 100이고 하루 표본이 넉넉하면(`emaAlpha × (100 − 60) ≥ maxDriftPerDay`) 하루에 딱 `maxDriftPerDay`씩 → 30 → 60은 ⌈30 ÷ 2⌉ = 15일, 55를 넘는 순간(56)은 13일째.
- **글자**: 점수 > `flipHysteresis[1]`(55)면 뒤 글자, < `flipHysteresis[0]`(45)면 앞 글자, 사이면 그대로. 바뀌면 자동 토스트 '성격' + 활동 기록 '성격' 한 줄: "이름 성격이 T → F로 바뀜 · 이유" (이유 = 그 축 · 새 글자 쪽 이유 문장, N은 "N으로").
- **바뀌는 중** (`drifting`): 목표가 뒤집히는 선을 넘은 축(지금 앞 글자면 목표 > `flipHysteresis[1]` 55, 뒤 글자면 < `flipHysteresis[0]` 45) 중 넘은 만큼이 가장 큰 축 (같으면 E/I → S/N → T/F → J/P 순). 목표가 50~55(45~50)면 점수가 거기서 멈춰 글자가 안 바뀌므로 바뀌는 중이 아니다 (M8 리뷰: 50 기준이면 목표 53.3에서 "T가 F 쪽으로 94%"가 영영 떴음). 퍼센트 = 글자 기준점(앞 글자 25 · 뒤 글자 75)에서 뒤집히는 선(55 · 45)까지 간 비율, 반올림해 0~99. 없으면 `null`. 화면 "T가 F 쪽으로 38%". 표본이 들어올 때만 다시 계산한다.
- **이유 문장** (`reason`): 새 표본에서 |표본 값 − 직전 목표(목표가 없었으면 점수)|가 가장 큰 축 (같으면 축 순서), 표본 값이 크면 뒤 글자 쪽·작으면 앞 글자 쪽. 그 쪽 세부 지표 중 이번 표본에서 가장 큰 것(아래 표 순서가 동점 순서)의 문장. 차이가 모두 0이면 전 문장을 둔다. 세부 지표 크기: E/I 동시 = 겹친 비율 · 참석 = 1 − 불참 · 혼자 = 1 − 겹친 비율 · 불참, S/N 도구 수, T/F 낱말 수, J/P 순서·재시도·전환 비율 (앞 글자 쪽은 1 − 비율).

| 축 | 앞 글자 쪽 문장 | 뒤 글자 쪽 문장 |
|---|---|---|
| E / I | 동시: 다른 팀원과 같이 일하는 때가 많아서 · 참석: 회의에 꼬박꼬박 나와서 | 혼자: 혼자 긴 작업이 많아서 · 불참: 회의에 잘 안 나와서 |
| S / N | 읽기·검색: 파일을 꼼꼼히 읽고 찾아봐서 · 작은 편집: 조금씩 나눠 고쳐서 · 테스트: 테스트를 자주 돌려서 | 새 파일: 새 파일을 자주 만들어서 · 웹: 웹 검색을 자주 해서 · 큰 편집: 한 번에 크게 고쳐서 |
| T / F | 보고에 원인·오류 이야기가 늘어서 | 보고에 칭찬·고마움 말이 늘어서 |
| J / P | 순서: 만든 순서대로 끝내서 · 재시도: 다시 시도하는 일이 적어서 · 전환: 한 도구로 차근차근 이어 가서 | 순서: 작업 순서를 자주 바꿔서 · 재시도: 실패한 도구를 자꾸 다시 시도해서 · 전환: 도구를 자주 바꿔 가며 일해서 |

- **개인 정보**: 표본·점수·이유는 숫자와 위 고정 문장뿐. 메시지 원문은 실행의 `lastMessage`(수집기 요약본)에만 있고 성격 상태로 옮기지 않는다.
- 씨앗: 표본이 하나도 없는 팀원은 roster가 다시 읽힐 때 직업 `mbtiSeed`로 다시 씨앗(직업이 바뀔 수 있어서), 회의 참가 시각(`lastMeetingAt`)은 둔다.

### 8.1 상단 바

- 화면 메모 (M7·M12): 금고 = 팀원 잔고 합(떠난 팀원 포함, 경제 패널 막대 합과 같음), 마을 기금 = 팀장(시장)의 지갑(6.5, `economy.fund`). 두 칩 모두 진짜 `<button>`(`--lift-press`). 기금 칩 글자는 "마을 기금 N". 시청 적자(`economy.deficit`, 6.2)면 칩이 `--danger` 색이 되고 코인 아이콘이 막힘 아이콘(아이콘 이름 "시청 적자")으로 바뀐다 — 색만으로 알리지 않는다. 마우스를 올리면 뜨는 설명(title)이 적자일 때 "시청 적자 · 힌트", 아닐 때 "기금 설명 · 경제 패널 열기". 옛 물가 칩은 D20으로 없어짐.
- 화면 메모 (M14): 상단 바 레벨 칸(06 문서 6.4) = '마을 공사' 자리에 'Lv.N <시대>' + 이 레벨 안의 일 점수 막대 + '일 a / b · 기금 c / d'(기금 조건 = 공사비 + 그날 팀장 토큰값 청구, core `levelUp`과 같음). 누르면 경제 패널(진짜 `<button>`, `aria-label`·title에 전체 글자). 1200 폭 아래는 보조 글자를 숨기고 title에만 남기며, 상단 바에서 이 칸만 줄어든다(알림·설정 버튼이 밀리지 않게). 만렙(Lv.10)은 "최고 레벨" 글자. 금고·기금 칩은 그대로(기금 칩 = 시청 적자 표시). 남은 양 펼침 칸은 M20.
- 화면 메모 (M9): 알림 버튼 = 최근 알림 목록(토스트로 떴던 것, `state.toasts` 새 것부터 20개)을 버튼 아래 칸으로 열고 닫는다(`aria-expanded`, Esc·바깥 누르기·포커스가 밖으로 나가면 닫힘, Esc면 포커스는 버튼). 목록 칸은 스크롤되므로 Tab으로 들어갈 수 있다(`tabIndex=0` + 3px 링). 열면 **모두 읽음** = 아직 떠 있는 토스트를 전부 닫는다 → 뱃지 0. 뱃지 = 아직 닫지 않은 토스트 수(M5 그대로). 설정 버튼 = 설정 화면(`&settings`, 10장).

### 8.2 메인 (마을) — `ScreenMain`

- 가운데 마을. 드래그로 이동, 휠·버튼으로 확대/축소 (0.6~1.6), "전체 보기"
- 마을/격자 전환 토글
- 오른쪽 위 토스트: 최대 3개 쌓임. 층 올림·급여·성격은 자동으로 사라지고(막대가 줄어듦), 회의·실패는 직접 닫을 때까지 남는다
- 아래 활동 기록: 전체/작업/회의/경제/성격 필터, 최근 것이 위
- 오른쪽 팀원 패널: 팀원 카드(얼굴, 이름, 직업, MBTI, 상태, 지금 하는 작업, 잔고 — 팀장 카드는 잔고 자리에 마을 기금) + 외부 방문자
- 일터 누르기 → 일터 상세, 집 누르기 → 집 상세, 팀원 카드 누르기 → 그 팀원 집 상세, 캐릭터 누르기 → 카드 강조
- 캐릭터 누르기 (M16, 06 문서 8장 D26): 팀원·팀장·외부인 모두 1.2초 버둥 + 머리 위 상태 말풍선(팀원은 카드 강조도), 6px 넘게 끌면(터치는 0.3초 누른 뒤) 집어 들어 옮기고, 놓은 칸에서 원래 가던 곳으로 다시 걷는다. 화면 놀이 — 상태·이벤트에 안 남는다. 집 간판 = 주인 얼굴 + 이름표(06 문서 7장)
- 화면 메모 (M7, `screens/LiveApp.tsx`):
  - 주소 = 같은 페이지 `?project=<id>` + 상세 하나: `&building=<bid>`(M6) · `&house=<memberId>` · `&shop=<memberId>`(처음 고른 사는 팀원) · `&economy`. 라우터 없음, 새로고침·링크·뒤로/앞으로 모두 됨.
  - 팀원 카드 누르기 = 카드 강조(발밑 원판)도 하고 그 팀원 집 상세. 마을의 집 누르기(`house:<memberId>`, 떠난 팀원 집도) = 집 상세. 시설은 아직 누를 곳 없음.
  - 옮겨 가기: 바로 앞 기록이 가려는 주소면 `history.back()`, 아니면 새 기록(`history.state.from` = 떠난 주소). → 마을 → 집 → 상점 → "집으로" → "마을로"가 기록을 쌓지 않고, 닫은 뒤 뒤로가 상세를 다시 열지 않는다 (M6 `fromVillage`를 일반화).
  - 상단 바 금고·마을 기금 칩 → 경제 패널. 경제·집·상점의 "마을" 링크는 마을로.
  - 마을 전환 (M9): 상단 바 선택 = **새 기록**(pushState) → 브라우저 뒤로가 앞 마을로. 저절로 고른 마을(`/`, 옛 북마크)도 주소에 적는다(replaceState) — 안 적으면 닫기의 "바로 앞 기록" 비교가 어긋나고, 뒤로 간 `/`가 가장 최근 마을을 다시 골랐다 (M9 리뷰). 상세를 연 채 마을을 바꾸면 포커스는 드롭다운에 남는다 (상세를 닫을 때 포커스를 되돌리는 건 포커스가 사라졌을 때만). 바꾸면 상세를 닫고 선택(강조)을 풀고, 마을/격자 보기(`&grid`)는 그대로. 카메라는 그대로 둔다(마을 지도가 모두 16×16). 닫은 토스트 목록은 마을 id를 붙여 두므로 섞이지 않는다. 앞 마을의 SSE는 끊는다.
  - 토스트 자리: 상세를 연 동안 오른쪽 정보 패널을 비켜 선다 (건물 620, 집·상점 440). 집은 위도 "가구 옮기기" 버튼 줄 아래(64)부터 (M8 — 성격 토스트가 그 버튼 밑에 깔렸음). 경제 패널은 패널이 화면 전체라 마을과 같은 오른쪽 위. 토스트 제목은 빈칸에서만 줄바꿈(`keep-all`, "F로"가 F / 로로 끊기지 않게).
  - MBTI 칩 (M8, 팀원 카드·집 프로필): 글자 = `personality.letters`, 바뀌는 중인 글자만 `--slot5-tint` 바탕 + `--slot5-deep` 글자. 칩은 `role=img` + 이름 "성격 ISTJ, T가 F 쪽으로 38%"(바뀌는 축이 없으면 "성격 ISTJ"), 마우스를 올리면 "T가 F 쪽으로 38%". 성격 토스트(`--slot5-tint` 타일 + 성격 아이콘)는 자동 5초, 활동 기록 '성격' 필터.

### 8.3 격자 뷰 — `ScreenGrid`

- 건물이 적거나 비교할 때. 팀원 집 카드 줄 + 팀원 일터 카드 줄 + 공사 중(첫 일 전) 일터 칩
- 카드: 그림, 이름, 층, 게이지, 대기 칩, 주인 얼굴
- 화면 메모 (M9, `screens/grid/GridScreen.tsx`):
  - 주소 `&grid`(값 없음). 마을 칸 왼쪽 위 마을/격자 토글(`Toggle`, 캔버스). 바꾸기는 기록을 쌓지 않는다(replaceState). 상세를 열어도 `&grid`가 남아 닫으면 격자로 돌아온다. 격자는 마을 칸과 활동 기록 자리를 덮고(캔버스 1080×832), 마을은 지우지 않고 가린다 → 돌아오면 카메라 그대로.
  - 팀원 집 카드: 집이 있는 팀원 모두, 슬롯 순, 떠난 팀원은 흐리게(0.55). 제목 "이름의 집", 얼굴, 팀원 카드와 같은 상태 글자, "가구 N개 · M개 배치", 잔고. 캔버스의 "방 꾸밈 %"는 규칙이 없어 뺀다.
  - 팀원 일터 카드 (M13): 첫 일이 끝난 일터(1층 이상), 생긴 순. 그림(집과 같은 얼굴 간판), 이름, 오른쪽 층("1층"·"2층"·"3층"·"큰 건물"), 게이지 막대 + "일 점수 / 다음 층"(큰 건물은 "다 컸어요"), 대기 칩("자재비 대기"·"Lv.N 필요"), 주인 얼굴(`role=img`, 떠난 팀원은 흐리게). 제목 줄 "팀원 일터 · N곳 · 공사 중 a · 대기 b". 캔버스의 "어제·2일 전"은 게임 날이 활동 시간이라 뺀다.
  - 공사 중(첫 일이 안 끝난 일터)은 카드 아래 점선 칩 "공사 중 · 이름". 카드·칩 모두 링크(`<a href>`) → 일터·집 상세.

### 8.4 집 상세 — `ScreenHouse`

- 방 장면 (6×6 타일, 창문·액자 기본). 가구 배치, "가구 옮기기" 모드(드래그로 칸 이동, 겹침 금지)
  - 방 칸 규칙 (M7, `rules/furniture.ts`의 `canPlace`·`findSpot`): 칸 `(x, y)`는 0~5, `(0, 0)`이 뒤 모서리. 오른쪽 뒤 벽(둥근 창) = `y = 0` 줄, 왼쪽 뒤 벽(액자) = `x = 0` 줄 (iso라 x가 오른쪽 아래, y가 왼쪽 아래로 간다). `placed = { x, y, rot }`는 왼쪽 위 칸. 1×1은 `rot 0`만, 2×1은 `rot 0`이면 `(x, y)`·`(x+1, y)`, `rot 1`이면 `(x, y)`·`(x, y+1)`. 모든 칸이 방 안이고 그 팀원의 다른 놓인 가구와 한 칸도 겹치지 않아야 한다 — 바닥 층 러그도 칸을 차지한다 (의자를 러그 위에 겹쳐 놓지 않음, 캔버스 15 배치도 안 겹침).
  - 벽 가구(`against: "wall-right"`, 책장=유리병 선반)는 모든 칸이 `y = 0` 줄일 때만. 밖 가구(`outdoor`, 꽃밭=말미잘 화단)는 방에 놓지 않는다 → 사면 창고(`placed = null`), 옮기기도 창고로만. 마당에 심기는 나중.
  - 사거나 자동으로 산 가구의 자리(`findSpot`): 뒤 모서리부터 `x + y`가 작은 칸 순, 같으면 `x`가 작은 칸, 2×1은 그 칸에서 `rot 0` → `rot 1` 순으로 처음 놓이는 자리. 없으면 창고.
  - 옮기기: 놓을 수 있는 자리거나 창고(`null`)면 옮기고, 아니면 무시 (서버는 409).
- 오른쪽: 프로필(이름·직업·성격 칩 아래에 동물 이름 — 자동 변형이면 염색 이름 포함, D16), 성격 4축 막대, 지갑(급여·가구·토큰, 그 아래 효율 한 줄 6.6. 팀장 집은 지갑 = 마을 기금 — 세금·가구·팀장 토큰값, 시청 적자 안내), 가구 목록(배치/창고)
- 화면 메모 (M7, `web/src/screens/house`):
  - 옮기기 모드: 가구를 끌거나(잡은 칸 기준으로 따라감), 가구 버튼을 누른 뒤 화살표(→ x+1, ↓ y+1)로 한 칸, R로 돌리기(2×1만 — 1×1에서 R은 아무 일 없음, 막힘 안내도 없음). 모드를 오가면 누른 버튼이 사라지므로 포커스를 옮긴다: 들어가면 첫 가구(방에 없으면 첫 도구 버튼), 취소·저장하면 "가구 옮기기". 놓을 수 없는 자리는 끄는 동안 `--danger` 점선 칸 + 흐리게, 놓으면 제자리로 돌아가고 까닭 한 줄. 창고 가구는 "방에 놓기" = `findSpot`. 칸 검사는 core `canPlace` 그대로.
  - 저장 = 바뀐 가구마다 `PUT …/furniture/:fid` 한 번씩. 서버가 하나씩 검사하므로 지금 놓이는 것부터 보내고, 서로 자리를 바꾸는 경우(모두 막힘)는 하나를 창고로 뺐다가 나중에 놓는다 → 중간 상태에서도 겹치지 않음.
  - 방 안 팀원 캐릭터는 휴식 중일 때만, 빈 칸 중 방 가운데(3,3)에서 가까운 칸.
  - 지갑 (M12): 급여는 실행 단위(6.1)라 오늘 급여 = 마지막 정산 뒤 끝난 내 실행의 급여 합(`AgentRun.wage`, 세전), 최근 급여 = 가장 새 실행(짝지어진 작업이 있으면 작업 이름, 없으면 에이전트 종류). 관리비 줄은 없다 (D20). 오늘 가구 구입 = 오늘(`clock.day`) 산 가구 값 합. 팀장 집은 큰 숫자가 마을 기금("시청 금고 = 마을 기금"), 급여 줄이 "세금 · 오늘"(`economy.today.tax`), 토큰 줄이 "팀장 토큰값 · 오늘"(`today.leaderTokens`)이고, 형편이 어려움 대신 시청 적자를 알린다.
  - 성격 카드 (M8, 캔버스 SeaScreenHouse): 제목 옆 글자 4개(바뀌는 중인 글자만 라벤더), 오른쪽 한 줄 "최근 작업 20개로 계산 · 하루 최대 2%"(`window`·`maxDriftPerDay`, 표본이 없으면 "직업 기본 성격 · 작업이 끝나면 조금씩 바뀌어요"). 축마다 양 끝 글자 + 트랙 안 `flipHysteresis` 띠(45~55, `--sunk`로 연하게) + 가운데 선 + 점수 원. 바뀌는 중인 축은 트랙 `--slot5-tint`, 원 `--personality`, 아래 한 줄 "T가 F 쪽으로 38%"(`--slot5-deep`, 조사는 N만 "N이"). 카드 끝에 이유 문장(`reason`). 캔버스의 "38% → 26%" 이동 구간 막대는 그리지 않는다 — 어제 점수를 상태에 두지 않음.

### 8.5 일터 상세 — `ScreenBuilding`

- 큰 일터 장면(주인 얼굴 간판) + 층 스텝 (1층 · 2층 · 3층 · 큰 건물)
- 게이지 (일 점수 ÷ 다음 층 점수) + 다음 층 조건(일 점수 · 자재비 · 마을 레벨, 충족 여부) + 대기 칩
- 최근 일 (실행 8개: 작업 이름 또는 "<종류> 실행", +점수), 쌓은 일 ("실행 N번 · 일 점수 · 자재비")
- 이름 바꾸기
- 자세한 화면은 06 문서 13장. 주소 `&building=<일터 id>` (예: `w1%3Abackend-dev`)

### 8.6 가구 상점 — `ScreenShop`

- 사는 팀원 선택, 종류 탭(전체/쉬기/일하기/꾸미기), 가구 카드(색 변형, 가격, 보유 중)
- 오른쪽: 그 팀원 방에 놓아 보기, 결제 후 잔고 (팀장은 결제 후 마을 기금, D21)
- 화면 메모 (M7, `web/src/screens/shop`):
  - 놓아 보기 = 그 팀원의 실제 6×6 방을 줄여서 `findSpot` 자리에 자홍 점선(캔버스 17의 3×3 조각이 아님 — 칸 좌표가 6×6이고 기존 가구가 보여야 해서). 자리가 없으면 "창고에 들어가요", 밖 가구는 "창고에 들어가요"와 같게 처리(8.4).
  - 종류 탭(`tab`)·사는 팀원·천 색(`radio`)은 ARIA 패턴대로 고른 것만 Tab 자리(roving tabindex), ←/→(↑/↓)·Home/End로 옆 것을 고르고 포커스(끝에서 돌아감). 고른 천 색 테(2px 먹선)는 포커스가 없을 때만 — 포커스면 3px `--focus` 테.
  - 카드는 캔버스처럼 안쪽 여백 없이 그림 칸이 테두리까지(ui-card 16px 여백이면 이름 줄이 좁아 "노 / 트북"으로 끊김), 이름은 낱말 가운데서 끊지 않는다(`word-break: keep-all`).
  - 카드 버튼은 고르기(`aria-pressed`), 사기는 오른쪽 주 버튼 하나. 보유 중은 뱃지(개수)이고 다시 살 수 있다. 천 색 기본값은 그 팀원이 아직 없는 색 중 첫째(02 문서 6.2 "두 번째부터 다른 색").
  - 가격 = core `furniturePrice(kind, cfg)` (`basePrice` 고정, D20). 잔고가 모자라면 사기 버튼 비활성 + "진주가 N 모자라요". 그사이 잔고가 줄어 서버가 409면 같은 안내.

  - 키보드: 차트에 포커스 → ←/→/Home/End로 날·주를 옮기면 마우스와 같은 툴팁. 팀원 잔고는 막대 끝에 값이 다 있어 툴팁 없음

## 10. 설정

- 마을별 설정(tycoon.json 형식, `~/.subagent-tycoon/settings/<마을 id>.json`) 편집 화면: 팀원별 동물·직업·소품
- 게임 하루 길이, 회의 말풍선 표시 여부, 확대 기본값
- 수집기 주소 확인과 훅 설치 안내 (복사 버튼)
- 화면 메모 (M9, `screens/settings/SettingsScreen.tsx`): 주소 `&settings`(값 없음), 상단 바 설정 버튼.
  - **팀원** (이 마을 설정 파일 `~/.subagent-tycoon/settings/<마을 id>.json`): 떠나지 않은 팀원과 팀장의 동물·직업·소품. 동물·소품은 바다 이름으로 고르고 **정본 id로 저장**한다(05 문서 3.2, 헤드랜턴 → `glasses`). 햄스터 소품 칸은 "씨워크 헬멧 (고정)"으로 잠그고 저장 값은 그대로 둔다. 직업 = `jobPresets` + 기타(`fallbackPreset`). 저장하면 **바꾼 팀원만** 세 값을 적는다(그 팀원은 자동 배정이던 값도 고정). 하루 길이도 바꿨을 때만 — 사용자 파일은 되도록 덜 건드린다.
  - **게임 하루** (같은 파일 `overrides.time.gameDayMs`): 활동 분 1~1440. 바꾸면 지금 날에서 이어 간다(6.2).
  - 손으로 적은 값이 목록 밖이어도(`"job": "devops"`, 모르는 동물·소품) 그 팀원의 **지금 값과 같으면** 받는다 → 다른 칸만 바꿔 저장할 수 있다. 화면도 지금 값을 선택지 맨 앞에 id 그대로 보인다 (M9 리뷰).
  - 폼은 브라우저 기본 검사를 끈다(`noValidate`) — 하루 길이가 분 단위가 아니면(e2e 2초) 손대지 않은 칸 때문에 저장이 막혔다. 검사는 화면 코드가 한다.
  - 저장 = `PUT /api/projects/:id/settings`(02 문서 9장). **사용자 프로젝트 폴더에는 쓰지 않는다 (D14)** — 타이쿤 저장 공간 `~/.subagent-tycoon/settings/<마을 id>.json`(DB 폴더 옆 `settings/`)에 쓴다. 본문을 검사하고, 그 파일이 깨졌으면 쓰지 않고(409), 쓰기 전 원래 파일을 `.bak`으로 복사하고, 임시 파일에 쓴 뒤 바꿔 끼운다. 모르는 키(`$comment`, `projectName`, 다른 `overrides`)는 그대로 둔다. 우리 파일이 아직 없고 프로젝트에 옛 `.claude/tycoon.json`이 있으면 그 내용을 **읽어서** 시작값으로 쓴다(그 파일은 건드리지 않음). 저장하면 화면에 쓴 파일과 백업 경로를 알린다. 수집기는 곧바로 팀원 목록을 다시 읽어 roster 줄을 남긴다 → 재생해도 같다.
  - **표시** (이 브라우저 `localStorage`, 마을 공통): 회의 안건 글자(프롬프트 앞 20자) 보이기 — 개인정보라 끄면 말풍선·팀원 카드·활동 기록·알림 모두 "…"/"광장 회의 시작"까지만, 거품 효과(캐릭터 거품·물기둥 거품·단계 바뀜 거품. 꺼도 포즈는 움직임, 05 문서 5.3), 확대 기본값(전체 보기·0.8·1.0·1.2·1.4). 게임 상태와 무관하다. 운영체제 "움직임 줄이기"(`prefers-reduced-motion`)가 켜져 있으면 거품 효과 기본값이 꺼짐.
  - **훅 설치 안내**: 수집기 연결 상태, 훅 주소, 설치 명령 `pnpm connect <프로젝트 경로>`(훅만 나만 쓰는 `.claude/settings.local.json`에 — 사용자 프로젝트의 다른 파일은 건드리지 않음, 02 문서 1장), 손으로 넣을 때의 `examples/target-project/.claude/settings.json` 내용 + 복사 버튼. 마을이 하나도 없을 때의 빈 화면에도 같은 안내를 둔다.
